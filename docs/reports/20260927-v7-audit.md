# Audit: v7 for RBP-class no-op regressions and default drift (2026-09-27)

## What was audited

The RBP-gate bug (commit `fe84467`) survived because its regression guard
was a no-op: `rbp_matches_full` claimed to compare pruned vs unpruned but
ran `run(0.0)` on both sides. This pass looked for the same class in the
freshly-landed v7 work and across all `#[ignore]`/env-var paths.

## Findings

### 1. No new "doc says X, code does Y" defaults

Every env-var gate and v7 flag defaults to what its doc-comment claims:

### 2. `rbp_matches_full` — closed

Now `#[ignore]` with a full explanation; the contract is pinned by the new
`rbp_gate_semantics` test (asserts `theta0=0` -> 0 pruned nodes;
`theta0>0` -> nonzero).

### 3. Two unconditional behavior changes from v7 — document, don't revert

These are **intentional** per the v7 runbook Item 5, but they mean any
measurement taken before vs after v7 is not a like-for-like comparison:

1. **RNR default iters 400 -> 2000** (`cham-search/src/trigger.rs:29`).
   The measured river solve at 400 iters was 13.15 ms against a 250 ms
   live cap (19x headroom unused); 2000 was chosen to use some of it.
   Effect: search benches and ladder rows recorded after v7 use 5x the
   compute.

2. **Leaf continuation blend wired into the live solve path**
   (`cham-search/src/prior.rs:157` `LEAF_BLEND_WEIGHTS = [0.6, 0.2, 0.2]`,
   `solve.rs` consults `blended_leaf_prior` on every branch). Per the
   runbook (v7 Item 5.3, DeepStack B-7), a single fixed leaf continuation
   is itself exploitable; blending 2-3 perturbed continuations reduces
   that. Effect: search benches and ladder rows recorded after v7 use the
   blend. There is no flag to revert to the single-continuation path.

### 4. Tests pinning the new defaults

`crates/cham-search/tests/search.rs:513` already asserts the RNR default
change ("default RNR iters raised 400 -> 2000"). The leaf blend weights
are not asserted anywhere outside their own definition; adding a test
would lock the constant:

    // crates/cham-search/tests/search.rs
    #[test]
    fn leaf_blend_weights_are_canonical() {
        assert_eq!(cham_search::prior::LEAF_BLEND_WEIGHTS, [0.6, 0.2, 0.2]);
    }

Optional; the runbook documents the value.

## Suggested follow-ups

- None urgent. The audit found no bug of the RBP class. The two
  unconditional changes are documented in the v7 runbook and pinned by
  tests where they matter.
- When the honest tiny agent finishes, its LBR/fallback numbers are the
  first to be compared against the pre-v7 baseline. Note that the search
  changes affect ladder/search rows but not the blueprint-level LBR bench
  (`benches/exploitability.rs` uses the raw policy, no search).
