# D2 experiment — command + protocol

Plan: docs/reviews/CHAMELEON-SOTA-PLAN.md line 113:
> **D2:** PCS at <= 4 h wall beats shipped bundle's VBR by > 3 SE *and*
> is monotone-decreasing in iterations.

## The comparison

- **Baseline (shipped):** `agent-honest-19dim/robust`, VBR
  `8.5196 +/- 0.6208` bb (180-board shuffled, ledger `fd12d00`).
  **D2 threshold: 8.5196 - 3*0.6208 = 6.657 bb.**
- **PCS arm:** `train-pcs` on the SAME abstraction
  (`config/abstraction-tiny.toml`, `artifacts/buckets-tiny`) for a 4-hour
  wall budget, then measure with the same D1 harness.

## Train

    chameleon train-pcs \
        --iters 1000000 \
        --combos 30 \
        --config config/abstraction-tiny.toml \
        --buckets artifacts/buckets-tiny \
        --out artifacts/pcs-d2-<ts> \
        --wall-budget-s 14400 \
        --log-every 10000 \
        --force

## Measure

    env -i PATH="$PATH" HOME="$HOME" \
      CHAM_D1_BP=<out>/robust \
      CHAM_D1_CONFIG=config/abstraction-tiny.toml \
      CHAM_D1_BUCKETS=artifacts/buckets-tiny \
      CHAM_D1_BOARDS=180 \
      target/debug/deps/d1_fullgame_vbr-<hash> --ignored --nocapture

## Pass/fail

- **Pass:** VBR < 6.657 bb.
- **Fail with plateau:** VBR ~ 8.5 (PCS hits the same floor as the
  shipped trainer). Plan says: skip to W2 (abstraction) before more
  trainer work.
- **Fail worse:** VBR > 8.5. Investigate the trainer.

## Monotone check

`--log-every 10000` produces an iteration-vs-rows trace. A second
measurement at 100k iters (same command, `--iters 100000`) gives the
"more iters = lower VBR" data point.

## Runtime finding (2026-10-09)

`train-pcs` estimates **68.7 h for 1M iterations at 30 combos/side**
(4 iterations/s). The plan's D2 gate allows 4 h wall. At that rate, 4 h
allows ~58 000 iterations — a 17x shortfall from 1M.

**This is the actual D2 blocker, not the trainer.** The PCS walk's
per-iteration cost is dominated by the same per-node-per-combo work the
bridge had before its cap: the walk processes 60 combos across 4124
tree nodes each iteration. The `expand_classes_to_combos_capped` fix
applied to the **bridge**, not the **walk** — `run_pcs` takes explicit
ranges and does no capping.

### What D2 as written requires

Either:
1. **Speed up the walk by ~17x** so 1M iters fits 4 h. Candidates:
   memoize terminal CFVs by board, hoist per-node work, batch key
   derivation (plan C-3's v3 key split).
2. **Relax "1M iters"** to what 4 h allows and test convergence at
   that budget. The plan does not fix an iteration count, only a wall
   budget; 58k iters is what the budget buys at current speed.

### What to run now

A 4h-budget run at whatever iterations fit, to produce a **data point**
on the convergence curve. If VBR at 4h is already below 6.66 bb, D2
passes early. If it's not, we learn the convergence rate and can decide
whether more iters would help.

Command:

    chameleon train-pcs \
        --iters 50000 \
        --combos 30 \
        --wall-budget-s 14400 \
        --out artifacts/pcs-d2-4h \
        ...
