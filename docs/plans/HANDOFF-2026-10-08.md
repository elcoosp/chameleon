## 9. Gotchas (learned the hard way)

- **A `pkill -f nextest` in ANOTHER repo killed FOUR of our long test runs**
  (256s, 2455s, 2708s, 13636s). RUN DIRECT BINARIES, not `cargo nextest`,
  for anything long: build with `cargo test --no-run`, then invoke
  `target/debug/deps/<test>-<hash>` directly. Its name matches no other
  repo's kill pattern.
- **Disk is chronically near-full** (other repos: vautr 33G, flux 25G,
  kod 11G targets). chameleon's own `target/debug` can be deleted to free
  ~10G. `cargo clean` in an idle other-repo frees tens of G.
- **Concurrent `wr.sh` runs** truncate files and race `git index.lock`.
  Write files behind a guard (`[ ! -s "$f" ] && cat > ...`), and never
  `rm -rf` a lock the launcher created. Launchers must NOT remove locks.
- **env flags in key paths (C-4/rule 4):** `CHAM_SLOT_BUCKET`,
  `CHAM_COMPRESS_HISTORY` are process-global and change KEYS. At
  abstraction v>=3 they are config fields (hashed); at v2 they are still
  env. The rlf-full policies were trained at v2 WITH CHAM_SLOT_BUCKET=1 --
  set it when measuring them or every key misses (we hit a 26.6% fallback).
- **D1 harness:** the encoder MUST come from the policy's own buckets
  (`CHAM_D1_BUCKETS`), not `cfg_only`, and the seq MUST be recorded, or
  the blueprint query misses (coverage 0%).
- **Heredocs with ```bash fences inside get truncated** by the tooling.
  Use 4-space indentation, not fenced blocks, in generated files.
- `TrainerConfig` literals need `dcfr_alpha`/`dcfr_beta` fields.

    CHAM_AVG_DELAY=0 target/release/chameleon train-bp \

      --dcfr-alpha 1.5 --dcfr-beta 0.0
