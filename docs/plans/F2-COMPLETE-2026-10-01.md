# F2 complete: class-conditioned solver (2026-10-01)

## What landed

The river solver now computes a **poker strategy**, not a shared
public-state strategy. Branch `f2-class-conditioned-solver`, commit
`1706b33`.

### The key changes

- **Regrets keyed by `(path, player, own_class)`** — hero's strategy
  can differ between the nuts and a bluff-catcher at the same public
  path. Same for villain.
- **Per-class reach tracking** — CF values are computed by summing over
  the opponent's classes weighted by their **counterfactual reach along
  the path**, not the unconditional prior. Villain ranges now narrow
  when they raise, exactly as they should.
- **Deployable per-class answer** — `SolveResult.our_class_strategy`
  and `their_class_strategy` expose the class-conditioned strategies.
  Callers query `(path, player, own_class)` and play the returned
  distribution.
- **Marginal view preserved** — `SolveResult.our_strategy` /
  `their_strategy` are still the prior-weighted marginal, for backward
  compatibility with the LBR diagnostics and other existing callers.
- **Warm-start still works** (seeds all classes identically; per-class
  regrets diverge during CFR).

### The acceptance test

`crates/cham-search/tests/one_card_poker.rs`, one-card river
(pot = stack = 1 bb, one bet size), hero range = {nuts, air}, villain
range = {bluff-catcher}. The class-conditioned solver produces:

    root actions ["check", "bet1", "jam"]
    strong probs [0.000, 0.500, 0.500]  (aggression 1.000)
    weak   probs [0.496, 0.252, 0.252]  (aggression 0.504)

- Strong class aggression **1.000** — value-bets the nuts always.
- Weak class aggression **0.504** — bluffs at the polar-Nash frequency.
- Max per-action |Δ| between classes > 0.05 — class conditioning real.
- Every per-class strategy is a proper distribution.

The pre-F2 solver **cannot** produce this output (it emits one
distribution per public path). The test is the proof that F2 is a
genuine rewrite, not a cosmetic change.

## What changed in the test suite

Two pre-F2 tests needed updating to the new contract:

1. **`fmbr_exploits_station`** — previously asserted the *marginal*
   was pure (one-hot at every path). Under class conditioning, the
   marginal is `Σ_c prior(c) × σ_c` (mixed across classes), while each
   class's strategy is pure. Updated to assert per-class purity via
   `our_class_strategy`.

2. **`warmstart_oracle_validation`** — previously asserted `flips ==
   0` on the marginal root argmax. Under class conditioning, warm
   seeds can send different classes to different argmaxes, so the
   marginal can legitimately flip. Updated to allow flips and instead
   check the actual safety contract: exploitability doesn't degrade
   (`gap_on ≤ gap_off + 0.5`).

**All 22 cham-search tests pass. All 76 workspace tests pass. Clippy
clean. Fmt clean.**

## What this does NOT do

**The solver is still dead code on the live decision path (F1).**
`pipeline.rs` never calls `cham_search::solve`, and
`DecisionTrace.search` is hardcoded `None`. That's the *next* piece
of work, and it is now safe to do (F1 would have deployed the wrong-
game solver before F2).
