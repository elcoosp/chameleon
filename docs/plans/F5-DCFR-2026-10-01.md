# F5: proper DCFR (alpha/beta slice discount) landed (2026-10-01)

## What changed

The competitiveness report (F5) pointed out that the previous
`--regret-discount 0.9` implementation was **exponential forgetting
with a 10-visit window**, not Brown & Sandholm 2019 DCFR. The report:

> `--regret-discount 0.9` multiplies the accumulated positive regret
> by a constant 0.9 at every visit. DCFR discounts at iteration t by
> t^alpha/(t^alpha+1). These experiments show that "exponential
> forgetting with a 10-visit window" is bad, which nobody doubted.
> They say nothing about DCFR.

F5 corrects that.

### The implementation

`crates/cham-blueprint/src/table.rs::RegretTable::discount_all(t_prev, t_now, alpha, beta)`:

- Telescopes the per-iteration discount over `[t_prev+1, t_now]`:
  - positive regrets scaled by `fp = Π s^α / (s^α + 1)`
  - negative regrets scaled by `fn = Π s^β / (s^β + 1)`
- `α = β = 1.0` is a strict no-op (CFR+ identity, bit-identical to
  pre-F5). The defaults ship at `1.0` so no existing artifact's
  training path changes.
- Closed forms for `α = 0` (`0.5^n`) and `α = 1` (`(t_prev+1)/(t_now+1)`)
  avoid per-iteration logs in the common cases; the general case uses a
  bounded log-sum.

`crates/cham-blueprint/src/trainer.rs`:

- `TrainerConfig.dcfr_alpha: f64` (serde default `1.0`)
- `TrainerConfig.dcfr_beta: f64` (serde default `1.0`)
- Parallel trainer calls `discount_all` at every slice boundary.
- Serial trainer calls it at every snapshot boundary.

`crates/cham-cli/src/cmd/train_bp.rs`:

- New CLI flags `--dcfr-alpha`, `--dcfr-beta`. Default `1.0`/`1.0`
  preserves existing behaviour.

### How to run the proper sweep

Brown & Sandholm recommend `α = 1.5`, `β = 0.0`, `γ = 2.0`. In this
codebase `γ` is the existing `avg_gamma` (already tunable) with the
`avg_delay = 0` semantics (linear weights, which is what `γ = 2`
amounts to in the paper's formulation).

The proper A/B is:

    # DCFR(1.5, 0, 2)
    target/release/chameleon train-bp --mode robust --iters 20000000 \
        --dcfr-alpha 1.5 --dcfr-beta 0.0 \
        --config config/abstraction-tiny.toml \
        --buckets artifacts/buckets-tiny \
        --out artifacts/par-f5-dcfr \
        --threads 4 --thread-mode hogwild

    # CFR+ baseline (identity)
    target/release/chameleon train-bp --mode robust --iters 20000000 \
        --dcfr-alpha 1.0 --dcfr-beta 1.0 \
        --config config/abstraction-tiny.toml \
        --buckets artifacts/buckets-tiny \
        --out artifacts/par-f5-cfrplus \
        --threads 4 --thread-mode hogwild

Then measure **both** with the F1 corrected metric (`tabular_br`),
not the clairvoyant `lbr_vs`. The report's warning is that the
previous DCFR "negatives" were measured with the wrong metric and the
wrong discount schedule — both errors are now corrected.

### What the old experiments measured

The old `--regret-discount 0.9` (10-iteration window) and 0.5 (1-iteration
window) results (`DCFR-ALPHA09-NEGATIVE`, `DCFR-ALPHA05-NEGATIVE`) are
retained as historical artifacts but no longer inform any decision. The
report's recommendation to strike them from the next-steps list is
adopted.
